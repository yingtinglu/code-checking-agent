# ChatAgent 长期记忆 — 详细设计文档

## 1. 需求概述

### 1.1 核心需求

- **只存不会过时的信息**：用户偏好、行为反馈、项目信息、外部资源引用
- **不存会变的内容**：代码、文件结构、当前 bug、git 状态——这些实时读取文件
- **记忆提取限流**：不是每条消息都触发，由独立 Fork Agent 每 N 轮检查一次
- **Fork Agent**：继承主对话上下文，但只能读文件 + 写记忆
- **四类记忆**：偏好（preference）、反馈（feedback）、项目信息（project）、外部引用（reference）
- **autoDream**：自动整理记忆文件（合并重复、删除过时）

### 1.2 设计约束

- 基于 AgentDemo 现有 LangGraph 架构（`chat_agent/graph.py` 使用 `StateGraph` + `add_node` + `add_edge`），新增节点/边，不重构
- 使用 GLM-5.1 模型（与主 Agent 一致）
- 文件系统存储（Markdown + JSON），不引入数据库
- 与 CodeAgent `.cac/memory/` 模式一致（人类可读、可手动编辑）

## 2. 核心需求 → 实现对照

| 需求                | 怎么实现                                                     | 对应 Letta/Graphiti 的什么                                |
| ------------------- | ------------------------------------------------------------ | --------------------------------------------------------- |
| 记忆四分类          | MemoryBlock 加 `category` 字段 + 每个分类一个子目录          | Letta Block 有 `tags` 但无分类体系，需扩展                |
| Fork Agent + 限流   | MemoryExtractor 每 N 轮触发，独立 CCSChatModel + ToolRegistry | SleeptimeMultiAgentV4 的 `sleeptime_agent_frequency` 限流 |
| Fork Agent 工具约束 | 硬编码约束：必须先 search → 再 write → 最后 finish           | VoiceSleeptimeAgent 的 ToolRulesSolver                    |
| 记忆每轮重新加载    | build_context() 每轮调 compile() 编译记忆进系统提示词        | `_rebuild_memory_async()` 每步重编                        |
| autoDream 去重      | 三阶段：精确匹配 → MinHash 模糊 → LLM 语义                   | Graphiti node_operations.py 三阶段去重                    |
| autoDream 矛盾处理  | LLM 判断矛盾 → 旧条目标记 stale → 时序淘汰                   | Graphiti edge_operations.py 的 invalid_at 时序淘汰        |

## 3. 整体架构

### 3.1 现有 ChatAgent LangGraph 流程（不加改动）

```
用户输入 → [append_user_msg] → [build_context] → [call_llm] → [route_response]
                                        ▲              │
                                        │   ├─→ 有 tool_calls → [execute_tools] ──┐
                                        │   ├─→ 最终回复 → [save_response] → END  │
                                        │   └─→ 无需工具 → [save_response] → END  │
                                        └────────────────────────────────────────┘
```

### 3.2 记忆模块接入点

长期记忆有 4 个组件，分别接入现有框架的不同位置：

**① MemoryStore（存储层）**

- 位于 `data/memory/` 目录，每个分类一个子目录（preferences/、feedback/、project/、references/），每个文件 = 一个 MemoryBlock
- 被 `build_context` **读取**：编译成 XML 拼接到系统提示词（即"记忆注入"）
- 被 MemoryExtractor **写入**：提取对话中的记忆 → 创建 .md 文件
- 被 MemoryDream **读写**：去重时读取、淘汰后写回

**② MemoryExtractor（Fork Agent）**

- 不在 LangGraph 图内，是独立的 Python 类
- 由 `main.py` 对话循环触发：每 N 轮调用一次
- 内部使用独立的 ToolRegistry + CCSChatModel + 工具循环（与 DegradationAgent 一致）
- 提取结果写入 MemoryStore，下一轮 `build_context` 自动读取生效

**③ MemoryDream（autoDream）**

- 不在 LangGraph 图内，是独立的 Python 类
- 由 `main.py` 对话循环触发：条件满足时调用
- 内部使用同一个 CCSChatModel + 工具循环
- 对 MemoryStore 中的记忆做去重和淘汰

**④ memory_search（主 Agent 搜索工具）**

- 注册到 ChatAgent 的 `tool_registry`（在 `register_all_tools` 中）
- 主 Agent 在 LangGraph 图中通过 `call_llm` 调用此工具，主动搜索记忆

### 3.3 ChatAgent.__init__ 初始化变更

原有：`storage`、`_llm`、`tool_registry` 不变，`register_all_tools(tool_registry)` 不变

新增：

- `memory_store = MemoryStore(config.memory_dir)`
- `register_all_tools(tool_registry, memory_store)` — 签名变更
- `extractor = MemoryExtractor(_llm, memory_store)`
- `dream = MemoryDream(_llm, memory_store)`

### 3.4 完整数据流

```
用户对话 ──→ MemoryExtractor ──→ MemoryStore(.md 文件) ──→ build_context ──→ LLM 看到"记忆"
                │                                            ▲
                │ 提取                                        │ 编译成 XML
                │                                            │ 拼接到 system_prompt
                │
                └──→ MemoryDream ──→ 去重/淘汰 ──→ MemoryStore(.md 文件)

主 Agent 主动搜索：LangGraph → call_llm → memory_search → 返回结果
```

### 3.5 存储层结构

```
data/memory/
  MEMORY.md           索引
  preferences/        PREFERENCE 类
  feedback/           FEEDBACK 类
  project/            PROJECT_INFO 类
  references/         RESOURCE_REF 类
  每个文件 = 一个 MemoryBlock
```

## 4. 模块详细设计

### 4.1 MemoryStore（记忆存储层）

**文件**：`chat_agent/memory/models.py` + `chat_agent/memory/store.py`

#### 4.1.1 数据模型：MemoryBlock

每条记忆存为一个 `.md` 文件，frontmatter 存元数据，body 存内容：

```markdown
---
category: preference
title: 用户语言偏好
tags: [语言, 中文]
stale_type: non_stale
priority: normal
created: 2026-07-22T10:00:00
updated: 2026-07-22T10:00:00
recall_count: 0
---

- 用户使用中文交流
- 回复时优先使用中文
```

字段：

- `category`：preference / feedback / project / reference
- `title`：人类可读标题，也是去重时的匹配键
- `content`：记忆正文
- `tags`：标签，辅助搜索
- `stale_type`：`non_stale`（不会过时）/ `semi_stale`（偶尔会变）/ `stale`（已过时应删除）
- `priority`：`high`（始终编译进系统提示词）/ `normal`（按预算）/ `low`（不主动包含）
- `recall_count`：被注入系统提示词的次数，autoDream 用它判断记忆是否被使用

#### 4.1.2 CRUD 操作

| 操作 | 方法                                                         | 做什么                                                       |
| ---- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 创建 | `create_block(category, title, content, tags=None, stale_type="non_stale", priority="normal") -> str` | 根据 title 生成文件名 → 写入 .md 文件 → 重建 MEMORY.md 索引 → 返回 filename |
| 读取 | `read_block(category, filename) -> Optional[MemoryBlock]`    | 读取 .md 文件 → 解析 frontmatter → 返回 MemoryBlock          |
| 更新 | `update_block(category, filename, content=None, tags=None, stale_type=None, priority=None) -> bool` | 读取已有 → 更新传入的字段 + updated 时间戳 → 写回文件 → 重建索引 |
| 删除 | `delete_block(category, filename) -> bool`                   | 删除文件 → 重建索引                                          |

所有文件写入用原子操作（先写 tmp 再 rename），与 AgentDemo `Storage` 类一致。

#### 4.1.3 搜索

```python
search(query, category=None, tags=None, limit=10) -> List[MemoryBlock]
```

步骤：遍历 `list_blocks(category)` 的结果 → 对每条的 title + content + tags 拼接后做关键词匹配 → 返回匹配的条目（不超过 limit）。

#### 4.1.4 编译

```python
compile(budget_tokens=2000) -> str
```

步骤：

1. 调用 `list_blocks()` 拿到所有条目
2. 过滤掉 `stale_type=stale` 的
3. 按 priority 排序（high → normal → low）
4. high 始终包含，normal 按字符预算（budget_tokens × 1.5，即约 3000 中文字符）依次包含，low 不主动包含
5. 每个条目渲染为 XML：`<preference title="..." tags="...">内容</preference>`
6. 整体包裹为 `<long_term_memory>...</long_term_memory>`

如果没有任何记忆，返回空字符串。

#### 4.1.5 MEMORY.md 索引

`data/memory/MEMORY.md` 列出所有条目的标题和路径：

```markdown
# ChatAgent 长期记忆索引

- [用户语言偏好](preferences/language.md) — 用户使用中文交流
- [沟通风格](feedback/communication_style.md) — 学生口吻
```

每次 create/update/delete 后自动重建。Fork Agent 用它查看已有记忆。

#### 4.1.6 去重辅助（供 MemoryDream 调用）

**`find_duplicates() -> List[Tuple[MemoryBlock, MemoryBlock]]`**

步骤：遍历所有条目 → 对 title 做 normalize（去掉空格、标点，转小写）→ 按 normalize 后的 title 分组 → 返回同组内条目数 > 1 的

**`find_similar(threshold=0.9) -> List[Tuple[MemoryBlock, MemoryBlock, float]]`**

步骤（移植自 Graphiti `dedup_helpers.py`）：

1. 对每条 content 做 3-gram 切片（"我喜欢编程" → {"我喜欢","喜欢编","欢编程"})
2. 对每个 content 的 shingle 集合计算 MinHash 签名（32 个哈希值）
3. 将签名分成 8 个 band，每 band 4 个哈希值
4. 同一 band 中哈希值相同的条目对成为候选对
5. 对候选对计算 Jaccard 相似度 = 交集大小 / 并集大小
6. 相似度 > 0.9 的返回
7. 标题过短（< 6 字符）或 Shannon 熵 < 1.5 bit 的跳过 MinHash，直接交阶段 3

**`find_stale(max_age_days=90) -> List[MemoryBlock]`**

步骤：遍历所有条目 → 过滤 `stale_type=semi_stale` 且 `recall_count=0` 且 created 距今 > max_age_days

### 4.2 记忆注入（修改 `chat_agent/graph.py` 的 build_context）

**"记忆注入"做什么**：在 LangGraph 图的 `build_context` 节点中，把 MemoryStore 编译出的记忆 XML 拼接到 system_prompt 后面，让 LLM 在生成回复时能看到之前记住的偏好和反馈。

#### 逐步流程

**第 1 步**：`ChatAgentState` 新增 `memory_store: Optional[Any]` 字段

**第 2 步**：`agent.py` 中 `ChatAgent.__init__` 新增 `memory_store` 参数，初始化时传入

**第 3 步**：`agent.py` 中 `register_all_tools(self.tool_registry, self.memory_store)` 修改签名

**第 4 步**：`build_context()` 中注入记忆：

```python
memory_store = state.get("memory_store")
if memory_store is not None:
    from .config import Config
    memory_xml = memory_store.compile(budget_tokens=Config.from_env().memory_budget_tokens)
    full_system = f"{state['system_prompt']}\n\n{memory_xml}" if memory_xml else state['system_prompt']
else:
    full_system = state['system_prompt']
api_messages.append({"role": "system", "content": full_system})
```

**为什么每轮都编译**：Fork Agent 可能在上一轮更新了记忆文件，下一轮需要重新编译才能反映最新状态。这和 Letta `_rebuild_memory_async()` 的思路一致。

**空间预算**：`memory_budget_tokens = 2000`（约 3000 中文字符），占 GLM-5.1 的 160K 窗口约 1.25%。

### 4.3 MemoryExtractor（Fork Agent）

**文件**：`chat_agent/memory/extractor.py`

`ChatAgent.__init__` 中初始化：

```python
self.extractor = MemoryExtractor(self._llm, self.memory_store)
```

MemoryExtractor 和 MemoryDream 共享同一个 `self._llm`（CCSChatModel），因为它们不会并发运行。

#### 逐步执行流程

**第 1 步：判断是否该触发**

main.py 对话循环中，维护 `turn_counter`，每次用户发消息加 1。当 `turn_counter % memory_extraction_frequency == 0` 时触发。`memory_extraction_frequency` 默认 5。

**第 2 步：拼接上下文**

从 ChatAgent 的对话历史中取出最近几轮未压缩的 user + assistant 消息（不是全部历史），再读取 MEMORY.md 索引内容（让 Agent 知道已有哪些记忆），拼上专用系统提示词 `prompts/memory_extraction.txt`。

**第 3 步：启动工具循环**

创建独立的 ToolRegistry，注册 3 个工具：

| 工具            | 功能           | 参数                                                         |
| --------------- | -------------- | ------------------------------------------------------------ |
| `memory_search` | 搜索已有记忆   | `query, category=None`                                       |
| `memory_write`  | 创建或更新记忆 | `category, title, content, tags=None, stale_type="non_stale", priority="normal", filename=None` |
| `memory_finish` | 声明完成       | 无                                                           |

`memory_write` 的 `filename`：为空 → `create_block()`；非空 → `update_block()`。

**第 4 步：工具链约束执行**（参考 Letta ToolRulesSolver）

Fork Agent 必须按顺序使用工具：

1. 必须先调用 `memory_search` 检查已有记忆
2. 然后可以调用 `memory_write` 0 次或多次
3. 最后必须调用 `memory_finish`
4. 最多 8 轮工具调用，超时 30 秒

**第 5 步：写入记忆文件**

`memory_write` 被调用时，根据 filename 是否为空决定创建还是更新，调用 MemoryStore 的对应方法。

**第 6 步：结束**

`memory_finish` 被调用后，提取流程结束。打印日志（`[记忆提取] 完成`）。

**实现方式**：不使用 LangGraph 子图。在 `extract()` 方法中：

```python
def extract(self, recent_messages: List[BaseMessage], memory_store: MemoryStore):
    # 1. 构建系统提示词：加载 memory_extraction.txt + MEMORY.md 索引
    system_prompt = load_prompt("memory_extraction.txt", "")
    index_content = memory_store.get_index_content()
    full_prompt = f"{system_prompt}\n\n已有记忆索引：\n{index_content}" if index_content else system_prompt

    # 2. 构建消息列表
    messages = [{"role": "system", "content": full_prompt}]
    for msg in recent_messages:
        messages.append({"role": msg.type, "content": msg.content})

    # 3. 工具循环
    registry = ToolRegistry()
    registry.register("memory_search", memory_search_tool(memory_store))
    registry.register("memory_write", memory_write_tool(memory_store))
    registry.register("memory_finish", memory_finish_tool())

    for _ in range(8):  # 最多 8 轮
        response = self._llm.chat(messages, tools=registry.get_all_tools())
        if not response.tool_calls:
            break
        for tc in response.tool_calls:
            result = registry.execute(tc)
            messages.append({"role": "tool", "content": str(result), "tool_call_id": tc.id})
        if "memory_finish" in [tc.name for tc in response.tool_calls]:
            break
        messages.append({"role": "assistant", "content": response.content or "", "tool_calls": [tc.to_dict() for tc in response.tool_calls]})
```

#### 系统提示词

`prompts/memory_extraction.txt`：

```
你是记忆提取代理，在后台整理对话中的长期记忆。

## 你的工具

- memory_search(query, category): 搜索已有记忆
- memory_write(category, title, content, tags, stale_type, priority, filename): 创建或更新记忆条目
- memory_finish(): 完成提取

## 记忆分类（四类）

1. preference（偏好）：用户的个人偏好、习惯。如"喜欢中文回复""偏好简洁回答"。
2. feedback（反馈）：用户对 agent 行为的纠正。如"不要 mock 数据库""先给思路再动手"。
3. project（项目信息）：项目的技术配置、环境。如"Python 不在 PATH，用 .venv/Scripts/python.exe"。
   注意：只存不会轻易变化的配置，不存代码结构、文件列表等会变的信息。
4. reference（外部引用）：外部资源、学习材料。如"Letta sleeptime agent 模式"。
   注意：只存路径/名称，不存完整内容。

## 提取规则

- 只存不会过时的信息：偏好、反馈、项目配置、外部引用 → 存
- 不存会过时的信息：代码内容、文件列表、临时状态、当前 bug → 不存
- 不存对话内容本身：不要把用户提问或助手回答原样存入
- 合并而非重复：已有相关条目则更新，不创建新的
- 可以跳过：没有值得提取的信息时直接 memory_finish

## 流程

1. 先用 memory_search 检查是否已有相关记忆
2. 需要新建时用 memory_write（不传 filename）
3. 需要更新时用 memory_write（传 filename）
4. 完成后必须调用 memory_finish
```

### 4.4 MemoryDream（autoDream）

**文件**：`chat_agent/memory/dream.py`

`ChatAgent.__init__` 中初始化：

```python
self.dream = MemoryDream(self._llm, self.memory_store)
```

#### 触发条件

三个条件满足任一则触发：

1. 记忆条目总数 > `memory_dream_max_entries`（默认 30）
2. 距上次 dream > `memory_dream_interval_hours`（默认 24 小时）
3. 用户手动输入 `dream` 命令

#### 逐步执行流程

**第 1 步：获取锁**

调用 `memory_store.acquire_dream_lock()`。如果获取失败（另一个 dream 正在运行），跳过。

**第 2 步：阶段 1 — 精确匹配去重**

调用 `MemoryStore.find_duplicates()`：

1. 遍历所有条目，对 title 做 normalize（去掉空格、标点，转小写）
2. 按 normalize 后的 title 分组
3. 同组内条目数 > 1 的，保留 content 更丰富的，删除其余

**第 3 步：阶段 2 — MinHash 模糊去重**

调用 `MemoryStore.find_similar(threshold=0.9)`：

1. 对每条 content 做 3-gram 切片
2. 计算 MinHash 签名（32 个哈希值）
3. 签名分 8 个 band，每 band 4 个哈希值
4. 同一 band 哈希值相同的为候选对
5. 对候选对计算 Jaccard 相似度
6. 相似度 > 0.9 的交给阶段 3

**第 4 步：阶段 3 — LLM 语义去重 + 矛盾检测**

对阶段 2 找到的模糊相似对，逐对提交给 LLM：

1. 输入：两条记忆的 title、content、updated 时间
2. LLM 返回：
   - `duplicate`：同一信息的不同表述 → 保留更新的那条
   - `contradicts`：新信息使旧信息失效 → 旧条目标记 `stale_type=stale`
   - `unrelated`：无关联 → 两条都保留

**第 5 步：时序淘汰**

调用 `MemoryStore.find_stale(max_age_days=90)`：

1. 找出 `stale_type=semi_stale` 且 `recall_count=0` 且创建时间超过 90 天的条目
2. 删除这些条目

**第 6 步：释放锁 + 记录时间**

调用 `memory_store.release_dream_lock()`，写入 `.dream-last-run`（记录本次 dream 完成时间）。

**实现方式**：独立 Python 类，`run()` 方法实现：

```python
def run(self, memory_store: MemoryStore):
    # 1. 获取锁
    if not memory_store.acquire_dream_lock():
        print("[dream] 另一个 dream 正在运行，跳过")
        return

    try:
        # 2. 阶段 1：精确匹配去重
        dup_groups = memory_store.find_duplicates()
        for group in dup_groups:
            best = max(group, key=lambda b: len(b.content))
            for b in group:
                if b is not best:
                    memory_store.delete_block(b.category, b.filename)

        # 3. 阶段 2：MinHash 模糊去重
        similar_pairs = memory_store.find_similar(threshold=0.9)

        # 4. 阶段 3：LLM 语义去重 + 矛盾检测
        if similar_pairs:
            system_prompt = load_prompt("memory_dream.txt", "")
            for b1, b2, score in similar_pairs:
                user_msg = (
                    f"记忆 A: title={b1.title}, content={b1.content}, updated={b1.updated}\n"
                    f"记忆 B: title={b2.title}, content={b2.content}, updated={b2.updated}"
                )
                response = self._llm.chat(
                    [{"role": "system", "content": system_prompt},
                     {"role": "user", "content": user_msg}]
                )
                if "duplicate" in response.content.lower():
                    if b1.updated > b2.updated:
                        memory_store.delete_block(b2.category, b2.filename)
                    else:
                        memory_store.delete_block(b1.category, b1.filename)
                elif "contradicts" in response.content.lower():
                    if b1.updated < b2.updated:
                        memory_store.update_block(b1.category, b1.filename, stale_type="stale")
                    else:
                        memory_store.update_block(b2.category, b2.filename, stale_type="stale")

        # 5. 时序淘汰
        stale_blocks = memory_store.find_stale(max_age_days=90)
        for b in stale_blocks:
            memory_store.delete_block(b.category, b.filename)

    finally:
        # 6. 释放锁 + 记录时间
        memory_store.release_dream_lock()
        (memory_store.memory_dir / ".dream-last-run").write_text(
            datetime.now().strftime("%Y-%m-%dT%H:%M:%S")
        )
```

#### 系统提示词

`prompts/memory_dream.txt`：

```
你是记忆整理代理。你的任务是审查记忆系统中的条目，去除重复、解决矛盾、合并碎片。

## 你的工具

- memory_search(query, category): 搜索记忆
- memory_write(category, title, content, ...): 更新记忆条目
- memory_delete(category, filename): 删除记忆条目
- memory_list(category): 列出某类别下的所有条目
- memory_finish(): 完成整理

## 整理原则

1. 重复条目：合并为一条，保留最完整的版本
2. 矛盾条目：保留更新的，删除过时的（注意看 updated 时间）
3. 碎片条目：同一类别下多个短条目（< 50 字）可合并为一个综合条目
4. 过时条目：semi_stale 且 recall_count=0 且超过 90 天未更新 → 删除

## 流程

1. 先用 memory_list 查看各类别条目
2. 发现问题时用 memory_write 更新或 memory_delete 删除
3. 完成后调用 memory_finish
```

### 4.5 主 Agent 记忆搜索工具

**文件**：修改 `chat_agent/tools/__init__.py`

from .filesystem import register_filesystem_tools
from .memory_tools import register_memory_search_tool

def register_all_tools(registry, memory_store=None) -> None:

    if memory_store is not None:
        register_memory_search_tool(registry, memory_store)

### 4.6 PROJECT_INFO / RESOURCE_REF 特殊处理

**PROJECT_INFO**：

- 只存项目级不会变的信息：Python 路径、模型名称、API base URL
- 不存会变的信息：代码结构、文件列表、当前 bug、git 状态
- Fork Agent 的系统提示词明确指示"不存代码结构、文件列表等会变的信息"
- 主 Agent 需要会变信息时，通过 `read_file` / `list_directory` 工具实时读取

**RESOURCE_REF**：

- 只存路径/URL/名称：如"Letta sleeptime agent 模式"或"https://github.com/..."
- 不存完整内容：内容由主 Agent 通过工具实时读取
- `memory_search` 命中 RESOURCE_REF 条目时，主 Agent 看到路径，自行决定是否去读取内容
