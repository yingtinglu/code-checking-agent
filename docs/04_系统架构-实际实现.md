# ChatAgent 系统架构文档

代码仓退化识别 Agent 系统是一个基于 LLM 的智能分析工具，支持两种分析模式：

1. **远程平台分析**：调用 CodeQualityShow 平台 API，获取代码质量聚合数据，生成退化分析报告
2. **本地代码仓分析**：基于文件系统工具链，对本地代码仓库进行静态质量分析

两种模式共享底层的会话 Agent（LangGraph 状态机）、工具注册表、上下文管理等基础设施。

## 1. 总览

ChatAgent 是一个 CLI 代码质量审查 agent，基于 LangGraph 状态机编排，通过 OpenAI 兼容协议对接内部 CCS（maas-glm-5.2-aliyun）LLM，支持 MCP 工具调用、本地文件分析、跨会话长期记忆、断点续跑，以及独立的退化分析子流程。

系统分几个正交子系统：

| 子系统     | 核心模块                                                 | 职责                                                     |
| ---------- | -------------------------------------------------------- | -------------------------------------------------------- |
| 对话主图   | `graph.py` `agent.py`                                    | LangGraph 状态机：plan→act→reflect 循环、工具调用、收尾  |
| 上下文压缩 | `context.py`                                             | 四层压缩 L1-L4，工作副本 `_api_messages` 与存储分离      |
| LLM 客户端 | `client.py` `llm_adapter.py` `config.py`                 | 流式调用、代理绕过、重试退避                             |
| 工具体系   | `tool_registry.py` `tools/filesystem.py` `mcp_client.py` | 原生工具 + MCP 工具统一注册、检索预算/去重硬闸门         |
| 断点续跑   | `storage.py`(Conversation) + SqliteSaver                 | 节点级 checkpoint、崩溃续跑                              |
| 长期记忆   | `memory/`                                                | 后台 fork agent 提取记忆、`search_memory` 检索、48h 过滤 |
| 退化分析   | `degradation/` + `degradation_mcp_server.py`             | 两阶段：规则收集数据→LLM 出 JSON 报告                    |
| 存储与安全 | `storage.py` `guardrails.py`                             | JSON 文件会话存储、artifact 落盘、输入防护/PII/凭证      |

## 2. 入口与配置

**入口** `main.py`：交互式 REPL。命令：`list/new/load/delete/clear/title/resume/analyze/reports/back/folders/quit`。

启动装配（`main.py:main`）：

1. `Config.from_env()` 读环境变量（优先级 `CCS_* > ANTHROPIC_* > OPENAI_*`）。
2. `Storage()` 初始化（`data/conversations/` JSON 文件 + `data/tool_artifacts/` 存档）。
3. 创建 `SqliteSaver`（`data/checkpoints.sqlite`）checkpointer 单例。
4. `MCPClient` 连接 MCP server（`mcp_servers.json` 配置，stdio/sse/streamable_http）。
5. 构造 `ChatAgent`（注入 storage/mcp_client/checkpointer），`agent.chat(message)` 驱动对话。

**Config**（`config.py`）：数据类，从环境变量加载 model/api_key/api_base/max_tool_iterations/quality_api_base/mcp_servers。`_load_mcp_config` 支持 list 与 Claude Desktop 两种 JSON 格式（自动转换）。

## 3. LLM 客户端层

### LLMClient（`client.py`）

**代理绕过两道防线**（公司 SWG 代理拦截）：

- 导入时清所有含 "proxy" 的环境变量（`:8-11`）。
- `httpx.Client(trust_env=False)`（`:69-72`），OpenAI SDK 用此 client。

**流式必需**：`chat_stream()`（`:133`）始终 `stream=True`，手搓 URL `api_base + /chat/completions`，手动解析 SSE。原因：CCS 网关部分模型（maas-glm-5.2-aliyun）只开放流式路由，非流式 404。

**StreamChunk**（`:43`）：`delta`(内容) / `finish_reason` / `tool_calls`。流式累积 tool_calls（按 index 跨 delta 拼接 name+arguments），在 `finish_reason` 时一次性 yield 完整 tool_calls。

**重试退避**（`:258-296`）：`RateLimitError`/`APITimeoutError`/`APIError`/`httpx.TimeoutException` 指数退避（`2**attempt` 秒），打印限流头。`chat()` 非流式委托 `chat_stream` 累积。

### CCSChatModel（`llm_adapter.py`）

LangChain `BaseChatModel` 子类，`_stream` 包装 `chat_stream` → `ChatGenerationChunk`。`_get_client()` 懒加载返回底层 `LLMClient`。**graph 节点直接用 `llm._get_client().chat_stream()`**，绕过 LangChain 包装（call_llm/reflect/final_answer 都是此模式）。

## 4. 对话主图（graph.py）

LangGraph `StateGraph`，固定节点骨架 + LLM 在 `call_llm↔execute_tools↔reflect` 循环内自规划。

### 节点与边

```
START → append_user_msg
        → (load_memory | build_context)        # 条件1: ALLOWED_ROOTS 非空则 load_memory
load_memory → build_context
build_context → call_llm
call_llm → (execute_tools | final_answer | save_response)   # route_response
execute_tools → reflect                        # 工具后反思
reflect → (build_context | load_memory)        # route_after_reflect: continue/replan
final_answer → save_response → push_queue → END
```

### 节点职责

- **append_user_msg**（`:110`）：输入防护（sanitize_input 控制字符/SQL 注入拦截、敏感信息确认）、`context_manager.begin_turn()`+`append_user`、初始化 state（tool_iteration/search_iteration/reflect_decision 等）。
- **load_memory**（`:188`）：注入 search_memory 指令到 context（让 LLM 调 search_memory 检索 48h 内相关记忆）。
- **build_context**（`:381`）：构建 `api_messages`（`get_api_messages(failure_hint)` = system + _api_messages + hint）、触发压缩 `compress_if_needed`、硬裁剪兜底。
- **call_llm**（`:295`）：流式调 LLM（带 tools）。注入指令：首次(`tool_iteration==0`)→PLAN_INSTRUCTION（先出 `[计划]` 再调工具）；replan→REPLAN_INSTRUCTION；continue→临时注入 reflect_reasoning 引导下一步。收集 `response_text` + `tool_calls_result`。
- **execute_tools**（`:434`）：执行 tool_calls。**检索三件套+bash 去重硬闸门**（按 arg_hash 去重，重复跳过）+ **轮次预算**（search_iteration，到顶 route_response 强制 final_answer）。L1 工具结果分流（大结果落盘留投影）。返回 messages/tool_iteration/search_iteration 等。
- **reflect**（`:390`）：ReAct 反思。`chat_stream(tools=None)`，输出 `DECISION: continue|replan`（无 done——最终回答时机由 call_llm 决定），只存 state 不注入 context（避免破 turn 切分）。硬约束预算到顶不强制（route_response 守）。
- **route_after_reflect**（`:443`）：replan→build_context（call_llm 重出计划）；continue→`_route_after_execute`（add_allowed_path 则 load_memory，否则 build_context）。
- **final_answer**（`:337`）：迭代/预算到顶收尾。`chat_stream(tools=None)`，提示"基于已有数据输出完整详尽报告"。
- **save_response**（`:435`）：canary 检测（系统提示词泄露截断）、凭证/PII/有害内容过滤、`context_manager.append_assistant`、`storage.update_index`。
- **push_queue**（`:202`）：本轮对话片段深拷贝入记忆队列（供后台 fork agent 提取记忆）。

### plan + reflect 自规划机制

- **plan 折进 call_llm**（非单独节点）：首次 call_llm 注入 PLAN_INSTRUCTION，LLM 输出 `[计划]分步路线图[/计划]` + 第一个 tool_call（同一 assistant-with-tool_calls 消息）。避免单独 plan 节点的冗余 LLM 调用。
- **reflect 独立节点**：每轮工具后反思，决定 continue（还需工具）/replan（计划有误重出）。**无 done**——避免 reflect 过早判完成导致答案简短不全（最终回答时机由 call_llm 自身决定：不再调工具即回答 → save_response）。
- reflect_reasoning 通过 call_llm 临时指令（不入存储）引导下一步，不破坏 turn 切分。

### 检索硬闸门（防循环撑爆）

- `_BUDGET_TOOLS = (list_files, grep, read_file, bash)` 全部参与去重 + 轮次预算。
- **去重**（`execute_tools`）：arg_hash（关键参数稳定哈希）命中则不执行，返回"已检索过"。
- **轮次预算**（`search_iteration`，默认 15）：到顶 + 仍想调检索工具 → route_response 强制 final_answer。

## 5. 上下文压缩（context.py）

工作副本 `_api_messages`（内存活状态）与存储分离。`_cur_turn_start` 标记当前轮起点（保护当前轮不被丢）。四级阈值触发原地压缩：

| 级别 | 阈值                          | 机制                                                         |
| ---- | ----------------------------- | ------------------------------------------------------------ |
| L1   | 单条 tool result > 4000 token | **追加时即时**：大结果落盘 artifact，上下文留投影（archive_policy 决定：archive/inline/archive_ref/no_archive_raw） |
| L2   | 用量 > 70%                    | 历史轮的 `user` 文本（首部 ~100 token）+ 最终 `assistant` 回答（首尾 ~150 token）截断。**不动 tool_calls 骨架和 tool 结果**（L1 已保真） |
| L3   | L2 后 > 85%                   | 从最旧轮起丢，**bounded**（保至少 K=3 轮近期，不无限丢）     |
| L4   | L3 后 > 92%                   | **全量选择性滚动摘要**：数据源 `conversation.messages` 全量；按完整轮次分块（chunk_budget=30000）；滚动累积双输出（`[叙事]`user 需求+assistant 回答 + `[关键事实]`重要工具结果）；忽略工具 chatter；bounded ≤2000 token ≪ L3 工作副本 |

**统一口径**（`_total_tokens(hint)`）：含 system + _api_messages + hint + tools，L2/L3/L4 触发与打印同口径，避免"压缩后比 L2 后大"的口径错觉。

**特殊**：

- `[计划]` 在 assistant-with-tool_calls → L2' 保留（LLM 全程参照），跨轮 L3/L4 兜底。
- rebuild 时 `load_from_history(compress=False)`——避免 `_cur_turn_start=0` 时压缩空跑 L4。

## 6. 工具体系

### ToolRegistry（`tool_registry.py`）

统一注册原生 Python 工具 + MCP 工具。`get_all_tools()` 返回 OpenAI function-calling 格式。`call_tool()` 分派（先原生后 MCP）+ 瞬时错误重试（`_classify_error` 分 transient/permanent）。**reducer**（`(args, content) -> 投影`）+ **archive_policy** 决定工具结果落盘/投影。

### 原生文件工具（`tools/filesystem.py`）

- **白名单路径**：`ALLOWED_ROOTS` 默认空，用户 `add_allowed_path` 显式授权。`validate_path` 相对路径依次试 PROJECT_ROOT + 每个 ALLOWED_ROOT（兼容 list_files 输出给 read_file）。`is_path_blocked` 拦 .git/.venv 等。
- **检索三件套**：`list_files`（文件名 glob，硬上限 100）、`grep`（指定文件列表内正则搜，files 必填控范围，per-file 50 命中，`>` 标记命中行+context）、`read_file`（带行号、100KB 截断）。
- **bash**：powershell 只读 cmdlet 白名单 + 危险 cmdlet 硬禁 + 重定向精确正则（避免误伤 `-gt`/`>500`）+ 输出设宽缓冲（防 Format-Table 窄截断）。
- **reducer**：`_list_files_reducer`（全留路径，工具结果喂 grep 用）、`_grep_reducer`（全留 path:line+命中行前 60 字符，压 context 行）。
- **search_memory**：检索 `.agent_memory` 记忆（见记忆子系统）。

### MCP（`mcp_client.py` + `async_utils.py`）

- `MCPClient` 管理 stdio/sse/streamable_http 三种 transport 的 MCP server。`connect()` 发现已启用工具，`call_tool()` 执行。
- **async/sync 桥接**：`async_utils.run_async()` 在后台 daemon 线程的事件循环上跑 MCP async 协程。
- **关闭 cancel scope 跨 task 修复**：每个 server 一个长期管理协程 `_serve_server`（enter + aclose 同 task），`shutdown` 用 `call_soon_threadsafe(close_event.set)` 触发关闭 + `task_future.result()` 等退出。避免 anyio cancel scope 跨 task 退出报错。

## 7. 断点续跑（checkpoint）

**SqliteSaver**（main.py 单例）→ `build_chat_graph(checkpointer=...)`。每节点（super-step）后自动持久化状态。

- **per-turn thread_id**（`f"{conv_id}#{turn_seq}"`）：避免 add_messages 跨轮累积。`turn_seq`/`active_thread` 存 Conversation（向后兼容）。
- **chat()**（`agent.py:157`）：`turn_seq += 1`、`active_thread = thread_id`、持久化、invoke、成功后清 `active_thread`。
- **续跑检测**（`_detect_and_offer_resume`，加载会话时）：读 `active_thread`，`graph.get_state` 查 `snap.next`（非空=未完成）→ 提示续跑 y/n。n=推迟（保留可续）。
- **resume_turn()**：`rebuild_from_checkpoint`（`load_from_history(compress=False)` + 重放 checkpoint 消息，幂等——artifact 按 tool_call_id 覆盖）→ `graph.invoke(None, config)` 续跑。
- 三道保险：进程内异常（main.py except 立即提示）、进程被杀（load 时检测）、chat 入口兜底（active_thread 非空先处理）。

## 8. 长期记忆子系统（memory/）

跨会话记忆，独立于对话主图。

### 生命周期

| 阶段     | 时机                  | 做什么                                                       |
| -------- | --------------------- | ------------------------------------------------------------ |
| 生成     | 每轮 save_response 后 | `push_queue` 深拷贝本轮 `_api_messages[_cur_turn_start:]` → `MemorySnapshot` 入队 |
| 后台提取 | daemon 线程异步       | `MemoryManager._run` 出队 → `fork_graph.invoke` → LLM 判断平台 vs 项目话题 → `fork_write_memory` 写 `.agent_memory/{category}/{title}.md`（带 `[saved: 时间]` frontmatter） |
| 读取     | load_memory 节点      | 注入指令让 LLM 调 `search_memory(project_path, query)` → 48h 硬过滤 + Jaccard 相似度排序 → top 5 |
| 过期     | 读取时                | `[saved: 时间]` 超 48h 不返回（文件留盘但不返回）            |

### fork agent（`memory/fork_graph.py`）

独立 LangGraph（`fork_build_context → fork_call_llm → fork_route`），用**独立 LLMClient**（不复用主 chat，隔离限流/预算）。工具 `fork_read_file`/`fork_write_memory`（create/update，Jaccard 0.4 预筛去重）。平台级话题（平台/中台等）输出 `PLATFORM_SKIP` 不写记忆。

### 存储

`{project_root}/.agent_memory/`，`memory_index.md` 索引 + 分类目录（`model_insight`/`user_feedback`）。Jaccard 按字符（中）/词（英）分词。

## 9. 退化分析子系统（degradation/）

独立的代码质量平台数据分析流程，**不复用主 chat 图**。

### 两阶段（`DegradationAgent.analyze`）

**阶段1：数据收集（规则驱动，非 LLM）**——`_collect_data` 按固定顺序调 MCP 工具：`get_domain_info` → `get_code_info` → `get_code_history` → `get_domain_detail` → `get_microservices` → `get_code_review`。

- `_called_tools` 去重（tool+args hash）。
- `_call_with_retry` 瞬时错误指数退避（最多 2 次），`_classify` 分 transient/permanent。
- 快照缓存（`DegradationStorage` sqlite，主键 month+base_month+repo_path，TTL 24h，关键工具全成功才写）。
- 质量门控：失败率 >50% 抛 `DataCollectionError`（不生成报告、不写缓存）。

**阶段2：报告生成（一次 LLM，纯 JSON）**——`_generate_report` 一次 `chat_stream`（无 tools），LLM 输出 `DegradationReport` JSON。

- `_extract_json`（直接解析→代码块→最外层{}→`_repair_truncated_json` 补全]}）。
- `_validate_report`（校验不阻断保存）。
- `DegradationReport.from_dict`（防御性构造，兼容旧 schema）。

### metrics 精简（`metrics.py`）

`simplify_code_info`/`simplify_domain_detail`/`simplify_code_history`/`simplify_microservices`/`simplify_code_review` 精简平台 API 响应。`METRIC_DEFINITIONS`（14 指标，api_field/threshold/direction）。`_extract_metric` 计算 trend/severity。

### 集成

- `degradation_mcp_server.py`：MCP server 薄层，转发 `QualityPlatformProvider`（HTTP 调 CodeQualityShow 平台）+ metrics 精简。
- `main.py:run_degradation_analyze`：新建独立 `LLMClient` + `DegradationAgent`，调 `analyze`，完成后 `get_followup_context` 注入追问上下文（报告摘要 + 数据摘要）给 ChatAgent 继续追问。
- **月份格式修复**：`data_provider._to_api_month`（yyyyMM→yyyy-MM），因平台 `transferMonthQuery` 只认 yyyy-MM。
- `skills.py` SKILLS 字典（5 stage）**仅定义未用**（预留扩展）。

## 10. 存储与安全

### 存储（`storage.py`）

- `Conversation`（id/title/messages/system_prompt/turn_seq/active_thread）：`data/conversations/<id>.json`，`index.json` 跟踪元数据。`from_dict` 用 `.get` 向后兼容。
- `Message`/`ToolCall`：消息 + 工具调用结构。
- `ToolArtifactStore`：大工具结果落盘 `data/tool_artifacts/<conv_id>/<safe_tc_id>.json`，**按 tool_call_id 确定性路径**（幂等，续跑重放安全）。

### 安全（`guardrails.py` + filesystem）

- `sanitize_input`：控制字符清除、长度限制、SQL 注入硬拦截。
- `detect_sensitive_info`：交互式确认发送敏感信息。
- `redact_pii`/`redact_credentials`/`filter_harmful_content`：输出脱敏过滤（save_response）。
- 文件工具白名单路径 + blocked 目录 + bash 只读 cmdlet 白名单。

## 11. 一轮对话完整数据流

```
用户输入
  ↓
append_user_msg: 输入防护 → context_manager.begin_turn + append_user
  ↓
load_memory(若有授权目录): 注入 search_memory 指令
  ↓
build_context: 构建 api_messages + 压缩(L1-L4 若超限) + 硬裁剪兜底
  ↓
call_llm: 流式调 LLM(带 tools)
  - 首次: 注入 PLAN_INSTRUCTION → LLM 出 [计划] + 第一个 tool_call
  - 后续: 注入 reflect_reasoning(continue) 或 REPLAN(replan)
  ↓
route_response:
  - tool_calls(预算内) → execute_tools
  - tool_calls(预算到顶) → final_answer
  - 无 tool_calls → save_response(LLM 直接回答)
  ↓
[execute_tools]: 执行工具(去重+预算+L1分流) → reflect → (continue→build_context→call_llm | replan→build_context→call_llm)
  ↓
final_answer(到顶收尾) 或 save_response(直接回答)
  ↓
save_response: canary/PII/凭证/有害过滤 → append_assistant → storage 更新索引
  ↓
push_queue: 本轮片段入记忆队列(后台 fork agent 提取)
  ↓
END → chat() 清 active_thread + 追加 messages 到存储
```

## 12. 关键设计决策

1. **plan 折进 call_llm + reflect 独立无 done**：plan 不单独调 LLM（避免冗余）；reflect 无 done（避免过早收尾致答案简短），最终回答时机由 call_llm 决定。
2. **工作副本与存储分离**：`_api_messages` 内存活、压缩；`conversation.messages` append-only 全量。L4 摘要读全量存储避免 lossy-on-lossy。
3. **统一 token 口径**：`_total_tokens(hint)` 含 system+hint，L2-L4 触发/打印一致。
4. **检索硬闸门**：去重 + 轮次预算 + bash 纳入，防 LLM 换工具绕过撑爆上下文。
5. **reflect 不注入 context**：作 user 破 turn 切分，作 assistant 破 LLM 思考；只存 state，经临时指令引导 call_llm。
6. **MCP cancel scope 同 task**：长期管理协程 enter+aclose 同 task，解决 anyio 跨 task 退出报错。
7. **代理绕过两道防线**：导入清 proxy env + httpx trust_env=False。
8. **artifact 按 tool_call_id 确定性路径**：续跑重放幂等。
9. **记忆 fork agent 独立 LLMClient**：隔离主对话限流/预算。
