### 2. 单个优化点文档（精选）

#### 优化点 15：串行改并行（数据收集）

- 类型：性能优化；适配：AI 应用架构师；状态：【建议补齐】；推荐：A
- 原始问题：`degradation/agent.py: _collect_data` 中 6 个 MCP 工具按序串行调用，对多域分析时逐域串行等待。
- 当前代码事实：`_collect_data` for domain 循环串行
- 优化方案：将互不依赖的工具调用（如多域的 `get_code_history`）改为并行编排，设统一超时与失败兜底
- Trade-off：并行带来的并发控制 vs 串行延迟
- 可写表述（建议补齐，不能写成已实现）："针对数据收集链路设计了并行编排优化方案，作为后续性能治理方向"
- 高频追问：哪些可并行？依赖怎么判断？
- 反吹牛：追问可并行边界
- 能写：数据收集并行编排方案（未实现）；不要写：已实现并行、QPS 提升 X%

#### 优化点 18：核心链路可观测性

- 类型：稳定性/工程治理；适配：稳定性/平台；状态：【建议补齐】；推荐：A
- 原始问题：当前有文件日志（`agent_log`）但无结构化 trace/metrics/token 统计
- 当前代码事实：`logger.py: agent_log` 写文件，无 trace、无 token usage 统计
- 优化方案：引入 LLM call trace、token usage、tool call log、命中率统计
- Trade-off：观测开销 vs 可定位性
- 可写表述：未实现，只能作优化方向
- 能写：可观测性治理方案（未实现）；不要写：已建可观测闭环

#### 优化点 19：Eval 评测体系

- 类型：AI 应用；适配：AI 应用架构师；状态：【建议补齐】；推荐：A
- 原始问题：退化报告无效果评测，长期记忆无命中率评估
- 当前代码事实：无 Eval 数据集、无评测脚本
- 优化方案：建立退化报告 Eval 数据集 + 长期记忆命中率指标
- 能写：Eval 体系建设方案（未实现）；不要写：已实现 Eval、准确率 94%

### 1. 克制专业版

## 十五、5 分钟深挖版本

1. **项目背景**：团队代码质量长期依赖人工审查，退化问题滞后发现。需构建能自动诊断代码退化的 Agent。
2. **系统定位**：AI 应用 / Agent 工程，支持远程平台聚合数据 + 本地代码仓两种分析模式，单机 CLI 形态。
3. **核心链路**：用户输入 → LangGraph 状态机（append_user_msg→load_memory→build_context→call_llm→execute_tools→reflect→save_response→push_queue）→ 工具调用循环 → LLM 推理 → 报告。退化分析另走两阶段流水线；长期记忆由后台 fork agent 异步提取。
4. **我参与/负责的模块**：会话 Agent 状态机+ReAct 反思、上下文管理、工具注册表、文件工具安全、退化分析流水线、长期记忆、断点续跑、输入输出护栏。
5. **最核心 2-3 个技术难点**：①LLM 工具循环调用不可收敛；②长对话上下文膨胀；③长任务崩溃不可恢复。
6. **关键设计取舍**：①用参数哈希去重+轮次预算牺牲灵活性换收敛；②四层压缩（L2'/L3'/L4'）牺牲细节换容量（可取回）；③ReAct 反思只判 continue/replan 不判 done，避免过早收尾；④断点续跑单 active_thread 牺牲多未完成 turn 换简单。
7. **AI 应用能力**：Tool Use / Function Calling、Workflow 编排、ReAct 反思+Plan/Replan、上下文管理、Prompt 体系、失败兜底、长期记忆（agent memory）、断点续跑。**未做**：RAG（向量检索）、多智能体、Eval。
8. **系统优化与治理**：错误分类重试、工具冷却自愈、硬裁剪兜底、原子写、孤儿清理、文件化日志。**未做**：可观测性（trace/metrics）、Eval、降级熔断、autoDream。
9. **风险边界与后续演进**：无线上规模数据、无 AI 推理优化、无分布式存储。后续优先补 Eval 与可观测性。
10. **与目标 JD 匹配点**：AI 应用架构（强匹配 ReAct+Agent 治理+上下文+记忆+断点续跑）；AI 性能优化/分布式存储（不匹配，明确不主打）。

（本深挖版本每点都能接住追问：ReAct 讲 continue/replan 不做 done、防环讲双闸门、压缩讲 L2'/L3'/L4'、断点续跑讲 rebuild；不确定处保守表达，无指标不虚构。）

## 十六、最终结论

1. **最值得打的牌（5 张）**：①ReAct 反思+Plan/Replan；②检索防环机制（参数哈希去重+轮次预算）；③四层上下文压缩（L2'/L3'/L4'）+归档三策略；④断点续跑（checkpointer+resume+rebuild_from_checkpoint）；⑤Agent 长期记忆系统（fork agent+Jaccard+48h+search_memory+平台话题检测）。
2. **最不该硬吹的 3 个点**：①AI 推理优化（无证据）；②分布式存储（无证据）；③高并发/大规模（无线上规模）。
3. **5 年架构师定位包装**：主打"用 ReAct 反思+确定性硬约束治理 LLM 不可控性的 AI 应用工程化"，强调 trade-off 与工程治理。
4. **AI 应用架构师包装**：主打 ReAct Agent 工具调用治理 + 上下文容量治理 + 长期记忆 + 断点续跑 + Workflow 编排 + 安全边界。
5. **Agent / RAG / Workflow 包装**：主打 ReAct Workflow 状态机 + 工具治理 + 防环防冷却 + 断点续跑 + 长期记忆；**不写 RAG**（无证据）。
6. **平台架构师包装**：主打统一接入层 + 分级授权 + 路径白名单 + 只读沙箱 + SQLite 缓存/checkpoint + 文件化日志。
7. **分布式 / 存储架构师**：不适合；保守表达为"数据访问/检索/平台工程"。
8. **AI 性能优化架构师**：不适合；无量化/算子/通信/GPU/Benchmark/Profiler 证据。
9. **只能选 3 条写进简历**：①ReAct 反思+Plan/Replan；②四层压缩+归档；③断点续跑。（若目标 AI 应用/Agent 岗，可将③替换为长期记忆系统。）
10. **只能选 1 条作为主讲点**：ReAct 反思+Plan/Replan（最能体现"用反思+硬约束治理 LLM 不可控"的架构师 trade-off，且是相对独特的动态规划能力）。
11. **最优先补的 3 个优化点**：①Eval 评测体系；②核心链路可观测性（trace/metrics/token）；③长期记忆 autoDream/矛盾检测/时序淘汰。
12. **最推荐投递岗位排序**：AI 应用架构师 > Agent/Workflow 工程师 > 平台工程师 > 稳定性/后端 > （不推荐：AI 性能优化 / 分布式存储）。
