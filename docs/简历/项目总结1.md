# 代码仓退化识别 Agent 系统 — 简历分析报告 v2

> 本报告严格依据《简历提示 Prompt》17 章输出结构生成，基于**当前代码**事实。所有结论以代码、配置、调用链为证据，区分【代码已实现】/【强推导亮点】/【可扩展设计】。候选人定位：5 年及以上架构师。未虚构 QPS/延迟/规模/准确率等量化数据。

## 一、项目技术画像

本项目是一个**基于 LLM 的代码质量分析 Agent 系统**，定位为 **AI 应用 / Agent / Workflow 工程化**项目。相比通用对话 Agent，它已演进为带 **ReAct 反思 + 计划/重规划 + 断点续跑 + 长期记忆**的工程化 Agent 系统。不是 AI 推理优化项目，也不是分布式存储项目。

- **系统类型**：AI 应用系统（偏 LLM 应用工程化 + Agent 工具调用编排 + ReAct 反思）。同时具备"数据平台 / 指标分析"属性（退化报告）与"中后台 / 平台工程"属性（统一工具注册表、分级授权、路径白名单、文件日志）。
- **主链路**：用户输入 → `main.py` REPL → `ChatAgent.chat()` → `LangGraph` 状态机（`append_user_msg → load_memory? → build_context → call_llm → route_response`；`call_llm` 有 tool_calls 则 `execute_tools → reflect → route_after_reflect`（continue/replan→build_context 循环）；收敛后 `final_answer/save_response → push_queue → END`）→ 工具调用（原生 / MCP）→ LLM 推理。远程退化分析另走 `DegradationAgent.analyze()` 两阶段流水线。长期记忆由后台 fork agent 异步提取。
- **关键业务对象**：对话会话 `Conversation`（含 `turn_seq`/`active_thread` 支持断点续跑）、`Message`（含 `pinned` 留 L3 保护扩展点）、`ContextManager`（工作上下文）、`MemoryManager` + `MemorySnapshot`（长期记忆）、`DegradationAgent`/`DegradationReport`、`ToolArtifactStore`（大结果落盘）、`ToolRegistry`（统一工具表）。
- **一致性 vs 可用性/吞吐**：偏**可用性 / 吞吐（上下文容量治理）**优先。核心矛盾是"LLM 长对话上下文膨胀"与"工具循环不收敛"，而非数据一致性。断点续跑用 `SqliteSaver` checkpoint 做节点级状态持久化，属单机可恢复性，非分布式一致性。存储侧用原子写（`Storage._atomic_write`）保证文件不损坏。
- **成熟度**：核心链路已落地可运行，且新增 ReAct 反思、Plan/Replan、断点续跑、长期记忆升级（独立 fork graph + Jaccard 去重 + 48h 硬判决 + search_memory 工具 + 平台话题检测）、L2/L3/L4 压缩重构（L2'文本压缩/L3'bounded/L4'滚动摘要）、文件化日志（`agent_log`）。存在悬空代码（`degradation/skills.py`、`degradation/tool.py: DegradationAnalysisTool`、`no_archive_raw` 策略、`submit_report` 工具注册未被 DegradationAgent 调用、execute_tools 临时测试钩子 `_chkpt_break`）。
- **最适合突出的架构师能力**：AI 应用链路工程化（ReAct 反思 + Plan/Replan + 工具调用治理 + 上下文容量治理 + 长期记忆 + 断点续跑）、平台工程化（统一工具注册表 + 分级授权 + 路径白名单 + 文件日志）、稳定性治理（防环 + 冷却 + 重试 + 护栏 + 硬裁剪 + 断点续跑 + 原子写）。
- **AI 应用架构 JD 匹配度**：**高**。LLM 应用、Tool Use / Function Calling、Workflow 编排、上下文管理、Prompt 体系（Plan/Replan/Reflect/full_summary/memory_extraction）、失败兜底（截断修复/硬裁剪/冷却/断点续跑）、长期记忆（agent memory）、ReAct 反思均有代码证据。
- **AI 性能优化 JD 匹配度**：**低**。未发现模型量化、算子、通信、GPU、Benchmark、Profiler 证据，**不建议主打 AI 性能优化**。
- **分布式 / 存储架构 JD 匹配度**：**低**。未发现大规模分布式存储、元数据、副本、一致性协议、数据分片证据，**不建议包装成分布式存储架构**，可保守表达为"数据访问 / 检索 / 平台工程"（仅本地文件 + SQLite checkpoint/快照）。
- **5 年架构师视角的最大价值**：把"LLM Agent 易失控（循环调用、上下文撑爆、编造数据、长任务中断）"这一类复杂系统问题，用一套**确定性硬约束（防环/冷却/预算）+ ReAct 反思（continue/replan）+ 断点续跑（checkpoint）+ 分层上下文压缩**体系解决，体现 trade-off 与工程治理能力。
- **最大短板**：无线上规模证据（QPS、DAU、并发量均不存在）、无 AI 推理底层优化、无分布式存储、单机 CLI 形态，难以支撑"高并发 / 大规模分布式"叙事。
- **作为主项目讲**：主打"AI 应用工程化 + ReAct Agent 工作流治理 + 上下文容量治理 + 长期记忆 + 断点续跑"。
- **作为次项目讲**：保守表达为"参与 LLM 应用链路工程化与工具调用治理"。

## 三、系统全景扫描

架构全景图（文字版）：

```
用户输入 (CLI REPL: main.py)
  -> ChatAgent.chat()  [chat_agent/agent.py]
     -> LangGraph StateGraph (compile(checkpointer=SqliteSaver))  [chat_agent/graph.py: build_chat_graph]
        -> append_user_msg  (输入防护: guardrails.sanitize_input/detect_sensitive_info; agent_log)
        -> [条件边1] _route_after_append: ALLOWED_ROOTS 有目录 → load_memory, 否则 build_context
        -> load_memory       (注入指令让 LLM 调 search_memory 工具)
        -> build_context     (压缩: ContextManager.compress_if_needed(hint); 失败缺口: _build_failure_hint;
                              硬裁剪兜底: _hard_truncate; 设子模块 conv_id)
        -> call_llm          (流式: client.chat_stream; 冷却屏蔽: cooldown_tools;
                              注入 Plan/Replan/Reflect 指令; agent_log)
        -> route_response    (条件路由: execute_tools / final_answer / save_response)
        -> execute_tools     (去重: search_called_tools + _search_arg_hash; 归一化: _normalize_tool_arguments;
                              授权: ConfirmationGateway; 分派: ToolRegistry.call_tool; L1落盘: append_tool_result;
                              测试钩子: _chkpt_break; agent_log)
        -> reflect           (ReAct 反思: REFLECT_PROMPT, decision=continue/replan, 不入存储只存 state)
        -> route_after_reflect (replan→build_context / continue→_route_after_execute)
        -> final_answer      (检索/迭代预算用尽强制收尾)
        -> save_response     (canary 检测; PII/凭证脱敏; 持久化: Storage; agent_log)
        -> push_queue        (深拷贝本轮片段 → MemoryManager.enqueue → fork agent 后台处理)
        -> END
     -> ContextManager  [chat_agent/context.py]  (L1落盘投影 / L2'文本压缩 / L3'bounded丢弃 / L4'滚动摘要; rebuild_from_checkpoint)
     -> ToolRegistry  [chat_agent/tool_registry.py]  (原生+MCP 统一; 瞬时重试 _call_with_retry; set_conv_id)
        -> 原生文件工具  [chat_agent/tools/filesystem.py]  (read_file/grep/list_files/bash/project_stats/search_memory/read_artifact; reducer)
        -> MCP 工具  [chat_agent/mcp_client.py -> degradation_mcp_server.py]
           -> QualityPlatformProvider  [chat_agent/degradation/data_provider.py]  (httpx → CodeQualityShow API)
  -> 长期记忆后台: MemoryManager daemon 线程  [chat_agent/memory/manager.py]
     -> fork_graph.invoke()  [chat_agent/memory/fork_graph.py]  (独立 LangGraph: fork_build_context→fork_call_llm→fork_route→fork_execute_tools/fork_finish)
        -> _FORK_TOOLS (fork_read_file/fork_write_memory); PLATFORM_SKIP 平台话题检测; Jaccard 预筛+LLM判断 create/update
        -> store.*  [chat_agent/memory/store.py]  (.agent_memory/ 文件; jaccard_similarity; 48h硬判决; search_memory)
  -> 退化分析支线: DegradationAgent.analyze()  [chat_agent/degradation/agent.py]
     -> _collect_data (规则序列 6 工具; 快照缓存; _CRITICAL_TOOLS 失败判定; DataCollectionError)
     -> _generate_report (LLM 直出 JSON; _extract_json + _repair_truncated_json; ReportValidator 校验)
     -> DegradationStorage  [chat_agent/degradation/storage.py]  (SQLite 快照 WAL TTL24h + 报告 JSON)
  -> ToolArtifactStore  [chat_agent/storage.py]  (data/tool_artifacts/<conv_id>/<safe_tc_id>.json; 原子写; 孤儿清理)
  -> agent_log  [chat_agent/logger.py]  (data/logs/<conv_id>.log; 调试输出落文件不污染终端)
```

- **模块划分**：`agent.py`（编排+断点续跑）、`graph.py`（状态机+ReAct反思+load_memory+push_queue）、`context.py`（上下文管理+四层压缩+rebuild_from_checkpoint）、`tool_registry.py`（工具注册表+set_conv_id）、`tools/filesystem.py`（本地工具+search_memory）、`guardrails.py`（护栏+set_conv_id）、`confirmation.py`（授权）、`mcp_client.py`（MCP客户端）、`client.py`（LLM客户端）、`storage.py`（会话存储+工具结果存档+Conversation.turn_seq/active_thread）、`logger.py`（文件日志）、`degradation/`（退化分析）、`memory/`（长期记忆：fork_graph/manager/store）、`async_utils.py`（异步桥接）、`llm_adapter.py`、`config.py`、`prompts.py`。
- **核心链路**：如上图。会话主链路为 LangGraph 状态机循环（含 reflect ReAct 反思）；退化分析为独立两阶段流水线；长期记忆为后台 fork agent 异步流水线。
- **核心表 / 存储**：`data/conversations/<conv_id>.json`（会话，含 turn_seq/active_thread）、`data/conversations/index.json`、`data/tool_artifacts/<conv_id>/<safe_tc_id>.json`（大工具结果存档）、`data/degradation/reports/<id>.json`+`index.json`（退化报告）、`data/degradation/cache.db`（SQLite 快照缓存）、`data/logs/<conv_id>.log`（文件日志）、LangGraph checkpoint（SqliteSaver sqlite，per-turn thread_id）。
- **缓存**：退化分析快照缓存（SQLite，`DegradationStorage`，TTL 24h，schema_version 版本控制）。会话上下文为内存工作集（`ContextManager._api_messages`），不落盘。LangGraph checkpoint（SqliteSaver）落 SQLite。
- **MQ**：未发现足够证据（无消息队列）。
- **定时任务**：未发现足够证据（无 scheduler/cron，仅启动时 `cleanup_orphan_artifacts`）。
- **外部依赖**：CodeQualityShow 平台 REST API（`httpx`）、LLM 端点（OpenAI SDK，统一走流式 `chat_stream`，因 CCS 网关对非流式请求返回 404）、MCP Server 子进程（stdio/sse/streamable_http）、SQLite（checkpoint + 快照）。
