# Skill 系统不适用分析

## 1. 背景

`chat_agent/degradation/skills.py` 定义了 5 个分析阶段 Skill：

- `scope_survey`：了解组织结构和时间范围
- `anomaly_detect`：定位退化指标
- `deep_dive`：下钻到具体团队/服务
- `cross_validate`：交叉验证结论
- `synthesize_report`：综合输出报告

设计目标是让 DegradationAgent 具备 Plan-Execute 自主规划能力，替代硬编码序列。

## 2. 试用结果

Skills 方案在实践中被发现存在严重问题：

- **重复调用工具**：LLM 反复调用同一工具，不收敛
- **无法收尾**：即使数据已充分，LLM 仍继续调用查询工具
- **分析周期过长**：达到 max_tool_iterations 上限仍无法输出报告

因此退化分析回退为硬编码的两阶段流水线（规则驱动数据收集 + LLM 直接输出 JSON）。

## 3. 原因分析

### 3.1 LLM 行为约束的技术限制

Skill 的 prompt_template 是软引导，LLM 可听可不听。即使 `synthesize_report` 明确写道：

> "不要再调用任何查询工具，唯一应该调用的是 submit_report"

LLM 仍可能忽略这个指示，选择"再查一个数据点更保险"。

**本质问题**：没有硬性约束机制强制 LLM 执行 `synthesize_report` 阶段的指令。

### 3.2 阶段判断依赖 LLM 自我评估

Skill 的 `enter_condition` 需要 LLM 自我判断当前处于哪个阶段。但 LLM 的判断不一定准确：

- LLM 认为"还需要一个数据点"但实际已充分
- LLM 认为"可以进入下一阶段"但遗漏了关键指标
- LLM 在多轮对话中丢失对当前阶段的追踪

这导致阶段切换不可预测，分析路径不确定。

### 3.3 开放域探索 vs 封闭域分析

Skills 适用于真正的开放域探索（如通用助手的多轮对话），但代码质量退化分析是**封闭域任务**：

- 分析目标是确定的：收集退化数据 → 生成报告
- 工具集合是固定的：6 个 MCP 工具
- 成功的定义是清晰的：提交结构化报告

对于封闭域任务，硬编码序列提供了更好的可预测性和可靠性。LLM 的"自由度"反而是噪音。

## 4. 硬编码序列的优势

| 方面       | Skills 方案           | 硬编码序列      |
| ---------- | --------------------- | --------------- |
| 执行路径   | 不确定，依赖 LLM 判断 | 确定，固定 6 步 |
| 收敛性     | 可能无法收尾          | 必然收敛        |
| 调试难度   | 高，LLM 决策不可见    | 低，步骤明确    |
| 数据完整性 | 可能遗漏步骤          | 6 个工具必执行  |
| 运行时间   | 不确定                | 可预估          |

## 5. 结论

**Skills 方案不适合当前系统**。

原因：

1. 试用了但效果不好，存在重复调用和无法收尾问题
2. 软引导无法可靠约束 LLM 行为
3. 代码质量分析是封闭域任务，可预测性优先于灵活性
4. 硬编码序列提供了更好的可靠性、可调试性和可预测性

## 6. 未来可能性

如需重新引入 Skills，应满足以下条件：

1. **强约束机制**：配合强制迭代上限、阶段强制转换，而非纯 prompt 软引导
2. **数据驱动判断**：阶段切换基于数据分析结果（如 `high_attention > 3` 触发下钻），而非 LLM 自我评估
3. **场景适配**：用于真正的开放域探索任务，而非封闭域分析

当前系统无此需求，硬编码序列已满足可靠性要求。

## 7. 本地代码分析也不需要 Skills

本地代码分析（graph.py 状态机）同样不需要 Skills，原因是已有的硬性防护机制已覆盖 Skills 想解决的问题：

| Skills 想解决的问题        | 本地分析已有的解决方案                               |
| -------------------------- | ---------------------------------------------------- |
| 重复调用工具无法收敛       | `search_called_tools` 去重表（MD5 参数哈希跨轮持久） |
| 检索循环无法收尾           | `search_iteration` 独立预算（15次上限）              |
| LLM 持续调用工具不输出结论 | `final_answer` 强制收尾节点                          |
| 全局迭代上限               | `max_tool_iterations`（默认20次）                    |

这些防护机制是硬性的，不依赖 LLM 的"自觉"。LLM 调用 `list_files` → `grep` → `read_file` 的过程本身就是 Plan-Execute 的体现——发现了线索就深入，没线索就基于已有数据输出结论。工具链的探索路径已经足够，Skills 提供不了额外的规划价值。

因此，**Skills 对整个项目都不适用**，无论远程平台分析还是本地代码分析。
